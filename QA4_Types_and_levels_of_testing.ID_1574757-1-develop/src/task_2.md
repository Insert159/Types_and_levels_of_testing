# Задание 2. Уровни тестирования (упрощённая версия)

## Таблица уровней тестирования

| Уровень тестирования | Что проверяем и на каком этапе | Кем проводится | Типичные артефакты (что создаём) | Пример дефекта (что сломалось) |
|----------------------|--------------------------------|----------------|----------------------------------|--------------------------------|
| Модульное | Проверка одной небольшой функции или метода сразу после её написания | Разработчики | 1. Набор модульных тестов (Unit-тесты) <br>2. Тестовые данные для функции <br>3. Отчёт о прохождении модульных тестов | 1. Функция `sum(a, b)` возвращает `a * b` вместо `a + b` <br>2. При делении на ноль программа падает вместо выдачи ошибки <br>3. Функция проверки возраста возвращает `true` для 16 лет, хотя нужно `false` |
| Интеграционное | Проверка того, как два модуля работают друг с другом | Разработчики и QA | 1. Тест-кейсы на взаимодействие модулей <br>2. Чек-лист проверки API <br>3. Данные для тестирования связей | 1. Модуль корзины не получает цену товара из модуля каталога <br>2. После регистрации пользователь не появляется в базе данных <br>3. Формат даты в одном модуле "дд.мм.гггг", а в другом "гггг-мм-дд" — данные теряются |
| Системное | Проверка всей программы целиком, все функции вместе |  QA | 1. Тест-кейсы для сквозных сценариев <br>2. Чек-лист регрессионного тестирования <br>3. Отчёт о результатах тестирования | 1. Пользователь зарегистрировался, но не может войти в личный кабинет <br>2. Приложение вылетает при попытке открыть историю операций <br>3. На русском языке в интерфейсе встречаются английские слова |
| Приемочное | Проверка того, что система готова к использованию реальными людьми | Заказчик | 1. Сценарии для приёмочного тестирования <br>2. Чек-лист проверки бизнес-логики <br>3. Акт приёмки или список замечаний | 1. Кнопка «Оплатить» находится не там, где её привык видеть пользователь <br>2. Программа не печатает чек, хотя по закону обязана <br>3. Система работает, но делает это очень медленно — пользователи жалуются |
